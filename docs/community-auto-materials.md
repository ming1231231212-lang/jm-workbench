# 每日自动准备与发布

每日计划可启用 `auto_prepare`，并设置 `search_terms`。目前接入日常 Chrome 本机模式的贴吧、掘金和知乎；旧计划默认关闭，其他平台拒绝配置。自动准备不要求清空已有素材，已有人工核对的内容优先使用。

## 执行顺序

1. 计划开始日期起，每天在发布时间前 60 分钟检查当日库存。发布仍按原时间、每天 1 篇文章和配置的 0–5 个不同原帖评论进行。
2. 库存不足时，在独立发现标签页读取公共列表，再打开原帖取得标题、正文和活动依据。贴吧按近期回复的列表，掘金读取人工智能最新列表，知乎搜索配置方向的文章；只使用已实现的文章评论入口。
3. 近 7 天的相关讨论可候选；7–30 天的讨论还须有至少 3 次页面显示的互动依据。无时间依据、广告、无关、本人和历史已接触目标排除。列表滚动与正文读取均有限量，不把搜索摘要当原文，不把全站热榜当原帖热度。
4. 文章独立生成，评论逐原帖生成。模型只处理公开标题、摘录、公开历史文案和已知产品背景，没有浏览器工具或发布能力。使用本机已有 OpenClaw 配置中的 OpenRouter 免费型号，不复制凭据，不自动切换付费模型。
5. 确定性检查原帖地址、原文锚点、关联文字、外链、长度、AI说明及历史相似度，再通过模型语义质检。网站介绍只放文章；自动发现普通讨论帖的评论不放链接或联系方式。模型失败、输出不完整或未过质量门槛时，保留已有素材并重查。
6. 素材保存到独立数据库表，发布调度器再创建冻结的任务快照。准备过程不能直接提交；结果不明、平台限制、人工暂停、账号或版本变化仍阻止发送。每个平台共享至少30分钟间隔、滚动24小时最多6项、当日1篇文章/5条评论。

## 模块职责

| 模块 | 职责 |
| --- | --- |
| `native_discovery.py` | 受限的原生列表/原文读取、时间证据、标题与URL核验 |
| `material_model.py` | 已配置文本模型的限时请求、生成与语义质检、格式补全 |
| `material_quality.py` | 来源、外链、原文对应、相关性、近期活动与相似度门槛 |
| `materials.py` | 当日缺口、持久素材池、模型调用、配置失效、重试和重启恢复 |
| `daily.py` | 发布计划、分类目标、素材选用、固定快照与原有每日队列 |
| `native_runtime.py` | Chrome互斥、原账号核验、提交前持久占位与发送边界 |
| `community-v2*` / `novice.js` | 自动准备设置、过程/正文、平台回执与网页登记分别呈现 |

`community_preparations` 保存每天过程、缺口、下次检查与公开来源证据；`community_materials` 保存通过检查的正文。素材绑定计划内容、账号版本、身份和代码版本的指纹；变更后旧素材不会意外进入新配置。

## 恢复与边界

- 准备失败按30、60、120分钟退避，当日每平台最多6轮，次日重新准备。目标不足不能为凑数发送无关或重复评论。文章准备不被原帖读取失败连带阻断。
- 读取过程中不持有每日计划锁，人工暂停可立即落库；保存前再核验计划、账号和平台状态。服务重启保留素材，准备中的状态改为等待重查。
- “检查素材缺口”接口只写入后台请求并立即返回；支持今天或明天，不改变原定发布日期、不创建发送队列。
- Chrome的UI自动化接口可能重复枚举同一RuntimeId，按同一元素处理。发现/身份检查标签被复用时可在原窗口新建只读任务页，保留被复用的页面；已关闭的未提交草稿可从任务正文恢复。原窗口或原进程变化仍停止，不更换浏览器配置。
- 屏幕可关闭，但本机原生操作要求电脑不休眠、Windows桌面可交互，且原账号仍登录。没有稳定公开接口时不能承诺平台每次都接受，也不能保证账号永不受限。
- `recorded` 是网页发布后登记的结果，不等同自动接口提交回执，更不等同未登录公开可见；首页按平台单独显示两类数量。
- 每日计划会关联当天同一账号和身份的真实 `submitted` / `recorded` 回执；必须已有结果链接，不修改原回执、不移动其他计划的记录、不创建发送。计划进度将两类计入完成数量，同时标明网页登记数量。已登记当天1篇/5评后，不再生成重复发送队列。
- 早期网页模式用 `manual:账号ID` 登记时，可归入同一账号容器的计划，但保留网页登记证据等级；已知身份与当前账号不同时拒绝关联。升级后的明确未提交任务支持主动“复核并继续今天”，复用历史续接守卫，保留旧快照与回执，新任务重新核验账号及预算。每日进度只统计每份内容的最新执行，旧尝试仍可查看。
- 悬浮窗遮住控件中心时，只能在同一控件矩形内选择仍属于原Chrome的可见点击位置，点击前复查；全部遮挡且尚未进入提交边界时按本地预检退避，进入提交边界后的异常仍判为结果不明。
- 原生按钮若提供UIA InvokePattern，只调用已核对控件一次，不向覆盖它的其他窗口发送坐标或按键；调用异常不再转坐标重试。贴吧同页有两个发贴入口时，仅在第一个明确被遮挡且未点击后尝试另一个，仍检查最终吧名与正文。
- 本人主页等待对应平台的本人操作标识和绑定昵称，不把先加载的导航栏判为已核验账号。富文本粘贴后若链接转换尚未完成，最多重新读取同一输入框3次，始终要求完整正文一致，不重复粘贴或放宽匹配。
- 后台 Windows PowerShell 5 与前台新版 PowerShell 都从剪贴板原始 CF_HTML 按 UTF-8 解码，避免系统 ANSI 编码破坏中文。复制序列变化才接受新结果，粘贴后不清空仍可能被 Chrome 读取的来源；正文与实际外链继续完整核验。
- 支持北京时间01:00开始、00:00准备。补发与正常任务共用滚动24小时额度，跨零点不会清空；工作台显示实际等待原因和可执行时间。

本次及后续验证以改动范围为准：只跑相关功能测试；未修改、未优化且不在测试计划内的模块不重复测试。

测试使用隔离数据库和模拟发布器，覆盖多天补充、库存耗尽、暂停/风险/版本变化、重启、重复原帖、相似正文、无依据热度、不同搜索查询、UI设置和单次提交边界。真实验收只读取必要公共页面及生成草稿，不为测试增加真实发布。
