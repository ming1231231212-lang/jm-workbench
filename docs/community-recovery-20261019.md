# 发布标签恢复与跨日进度

## 问题与修复

日常 Chrome 的已完成任务页可能后来变成主页或其他页面，持久绑定仍指向昨日结果页。原实现把网址不匹配当作永久预检错误，随后暂停整个平台的每日计划；在此之前的重试原因还会被最后一次错误覆盖。

新文章尚未填写、没有未决草稿时，原生执行器可以在已核对的同一窗口中新建任务标签；保留原标签、账号和资料目录。开始填写后不覆盖草稿。页面变化归为本机暂态：仅在未进入持久提交占位时退避重查；进入提交边界后仍为 unknown，只核验不重发。人工暂停与真实平台限制优先。

导航异常保存最近 20 次预期/实际路径，去除网址凭据和查询参数；任务回执保留最近 20 次预检原因，便于区分夜间桌面不可用与具体页面变化。

恢复成功后仍保留这些原因；当日完整目标的真实回执已齐全时清零旧的连接/缺口检查时间，下一动作回到下一日准备和执行。界面分别显示原计划日期、实际提交时间和网页登记时间，未知结果不显示为实际成功提交。

历史补发的 plan item 保留原计划日期与唯一 post_id。每日进度依据真实提交时间（网页登记依据登记时间）统计，`scheduled_counts` 独立保留原日计划统计。同步已关联的历史回执也会建立实际发送日的记录，重复同步不建立第二篇文章、不修改原快照。

## 验证范围

- 已完成标签被改用、未提交草稿保留、页面变化退避、提交后未知结果不重发、用户暂停优先。
- 历史帖子跨天提交/登记、重复同步、服务恢复、次日不重复计数。
- 三平台连续三天 01:00 仅发帖子模拟、共享额度、指定日期补排、禁评规则。
- 正式账号只补用户指定的原帖；真实结果及本机标识只保存在 outputs，不提交 Git。

自然日未来执行与未登录公开可见性必须以届时实际回执为准，模拟测试不替代真实结果。
