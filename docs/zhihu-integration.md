# 知乎网页发布接入

2026-10-14。入口：JM 工作台「平台账号 → 添加知乎」「内容与记录 → 写内容」。

## 使用流程

1. 添加知乎账号，打开网站，在日常 Chrome 完成登录。账号备注可保存本人主页，方便识别；网页模式不显示为自动执行已连接。
2. 发布专栏文章：选择知乎账号，填写标题和正文，保存草稿或准备网页发布。文章不需要填写贴吧式板块。
3. 评论原帖：选择「评论原帖」和知乎账号，填写原帖 HTTPS 链接及评论全文。支持专栏文章和具体回答；问题总页不作为具体回答的评论目标。
4. 打开平台，按平台原生编辑器完成提交。AI 辅助内容按知乎原生创作声明要求处理；验证码、登录、实名认证或账号限制需本人在平台处理。
5. 提交后登记真实链接。工作台显示「已登记 · 待核验」，正文、原帖、账号快照和结果独立保存。登记不表示已验证公开可见性。

文章目标示例：`https://zhuanlan.zhihu.com/p/624717941`。
回答目标示例：`https://www.zhihu.com/question/123456/answer/654321`（结构示例，不是已核验的业务目标）。

## 能力与约束

- 支持账号配置、文章/评论草稿、导出、日常 Chrome 网页交接及结果登记。
- `comment_draft`、`web_comment` 为真；`auto_publish`、`auto_comment`、`daily_plan` 为假。自动提交和每日自动执行尚未接入。
- 回答正文、想法和视频创作尚未作为新的内容类型接入。
- 工作台本地评论上限为 2000 字；实际提交仍受平台编辑器及账号权限约束。
- 同一账号配置的评论正文和原帖均有持久占位去重；追踪参数、片段和同一回答编号的不同问题路径不能绕过去重。
- 登记文章结果只接受已发布专栏文章 URL；登记评论结果必须对应原任务中的同一原帖，禁止登记登录页、编辑页、主页或其他帖子。
- 不建立浏览器扩展/CDP执行连接，不读取 Cookie，不更换浏览器账号、配置目录或 IP。工作台保留网页发布方式和既有暂停。

## 代码职责

- `community/zhihu.py`：文章/回答 URL、评论目标去重键、正文约束、同原帖结果校验，无网络提交代码。
- `community/registry.py`：公开能力及网页入口；`service.py`：冻结快照、事务占位和登记。
- `web/static/community.js`：按能力选择评论账号及目标输入；`community-v2-model.js`、`community-v2-views.js`：快捷入口和能力矩阵。
- `tests/test_zhihu_web.py`、`tests/zhihu.test.js`、`scripts/verify_zhihu_web_ui.py`：目标校验、去重、API、UI及无外部发布验收。
