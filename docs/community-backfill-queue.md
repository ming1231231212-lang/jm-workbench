# 历史补发执行

登记历史缺口、准备正文和安排实际发送是三个不同操作。`POST /api/community/backfill/{plan_id}/queue` 只处理指定原计划下已有完整内容的历史条目，需先核验原账号并显式启用计划。

没有发布任务的草稿经过现有 launch 建立占位。旧 paused / failed 任务只有 started=0 且能证明未提交时可续接；failed 必须有 preflight/submitted=false 回执。未知、已提交、人工登记、执行中以及已取消任务不重放。账号 ID、稳定身份、账号版本、正文与目标必须完全一致。

续接在一个事务中进行：保存旧状态和原因到 `community_backfill_continuations`，结束未提交的旧执行尝试，转移其去重占位，再为原内容建立当前版本的新执行快照。原 snapshot 与 receipt 不改。失败回滚整项；重复点击不会产生另一份任务。历史归属仍按原计划日，实际发送时间由执行器记录，状态展示以最新执行尝试为准。

补发与日常计划共用现有平台额度：每天1篇帖子、5条评论，30分钟间隔，滚动24小时最多6次。原计划暂停、全局停止、未知回执及平台风险锁均继续阻止执行。通过新计划项关联确保补发也响应原计划暂停；已显式登记的历史队列不因跨天被自动丢弃。

已安排的历史队列优先使用每日额度；有待发历史任务时，普通每日计划每30分钟核对一次，不额外堆积新队列。实际当日计数仍按真实提交时间统计，不把历史所属日改成今天。

不会为了凑数生成无关目标。缺少正文或相关原帖的条目继续显示待准备。长文关键词必须在同一条不超过240字的句子或标题中共同出现，不能把全文各处的词拼成相关主题。本文描述执行机制，不代表历史条目已经全部提交。

## 2026-10-18 指定日期补排

preview/register支持可选from_day，结束日仍为through_day；仅历史日期，起始不能晚于结束，范围受原计划创建日和开始日限制。注册只填充指定计划、指定日期的草稿，不触碰更早空缺或其他平台。历史队列支持贴吧、掘金和知乎，沿用原账号核验、发布适配器和未知结果保护。

POST backfill/{plan_id}/queue 可选JSON {"from_day":"2026-10-17","through_day":"2026-10-17"}，只安排范围内的明确未提交项。省略正文保留旧调用兼容。不会改变每天每平台1篇、间隔及滚动额度；草稿的schedule_at可设为次日01:00，经原队列保留到跨天执行，仍响应原计划暂停。
