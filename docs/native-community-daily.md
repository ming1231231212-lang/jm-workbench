# 日常Chrome社区发布与每日计划

工作台以 community_browser_execution=native 为显式本机执行方式，仅开放已实现的贴吧、掘金、知乎文字文章和顶层评论。其他网页平台、真实CSDN限制、原发布记录保持原状态；API平台继续原适配器，不切换到桌面操作。

## 用户流程

1. 在日常Chrome登录原账号，在账号管理核验本人主页。绑定账号版本、本人入口、显示名称和公开主页别名；已有账号身份不能替换。不会复制Cookie、装扩展、改Chrome资料目录、换IP或自动换号。
2. 每日计划填写开始日期、北京时间、文章素材、相关话题/分类和已核验原帖评论。保存保持暂停。明日计划不能通过“安排今天”提前执行。
3. 每平台每天最多1篇文章、5个不同原帖评论，所有账号共用30分钟间隔和滚动24小时6次预算。原帖和正文不重复；素材或合适目标不足时显示缺口，不能保证凭空补齐每日数量。
4. 在内容与记录中查看原文依据、实际正文和链接。account_visible 表示本人登录页面核实全文和作者，不等于未登录公开可见、推荐曝光或获客效果。

## 本机条件与限制

电脑需保持唤醒，Windows桌面可交互，日常Chrome保持原账号登录。锁屏、休眠、验证码、没有权限或平台页面改变会停止或延时检查。未实现无桌面发布，也不绕过安全验证。执行不要求原OpenClaw扩展或CDP连接；不保证零封禁。

## 架构

native_runtime负责跨进程桌面互斥和提交前持久占位；native_channel与native_chrome.ps1只操作已确认日常Chrome中的任务标签；native_articles和native_replies分开准备与核验，NativePublisher只有一次提交边界。账号核验使用独立任务标签，不导航覆盖未提交文章。已有草稿只允许恢复当前任务指纹与逐字一致内容。

任务标签同时保存窗口句柄、原进程ID与启动时间。每次操作重新核验窗口所属进程、程序路径与默认资料目录；进程或标签已变化即停止。首次连接仅接受唯一的日常Chrome，排除使用独立资料目录、调试端口或隐私模式的备用实例；其他任务启动备用Chrome不再阻断已绑定窗口。

贴吧会将网址显示成网页链接；原生剪贴板HTML中核验data-url，不能只根据显示文字接受链接。文字回读不忽略否定词或标点。账号昵称不能单独证明身份；只接受本人主页入口和内容区域作者链接。

提交前复查当前账号版本、内容快照、目标、代码版本、平台风险、用户停止状态、每日计划状态和共享预算。提交占位已保存或操作超时后，不重新点击。服务恢复将不确定请求锁定等待核验。只读预检的临时失败可重查；真实风险不能因重新登录解除。

## 评测边界

Python隔离模拟测试涵盖账号绑定、日期、共享预算、单次提交、重复内容/目标、用户暂停、原文变化、错作者、丢失段落、编辑器跳转、标签、链接和草稿恢复；Node验证工作台表单和记录。正式页面准备检查只进入草稿和相关设置，不以研发测试额外发布未经授权内容。公开 visibility 另行核验。


## 2026-10-15 空标题与暂态复制恢复

Chrome空标题的UIA TextPattern可返回U+FFFC对象占位符，而ValuePattern实际为空。复制空标题不会更新剪贴板；旧实现因此把空框判为复制失败。仅当ValuePattern存在且为空、TextPattern只有空白/对象占位符、控件无实际文本或嵌入内容时接受空值；真实文字、图片、链接和缺少值证据仍不接受。

显式本地复制暂未完成和桌面暂不可交互用NativeTransient分类；只有提交占位之前允许按现有5/10/20/30分钟退避重查。提交之后任何相同异常都保留NativeUnknown，不能重发。原账号变化、正文不一致、已有其他草稿、平台限制仍停止。每日只发一篇，评论0的规则不变。

相关86项测试通过，含实际PowerShell函数边界测试；真实知乎空标题/正文分别通过前台pwsh及后台Windows PowerShell读取，4项实机检查通过。真实发送只续接用户授权的当天原三篇任务。

贴吧contenteditable控件另需同时确认tb-editor-title/tb-editor-content、已观测的完整CSS提示、全选后的空选区、没有图片/链接等嵌入内容。提示语相同但实际可选文本非空时拒绝当作空框。三平台标题/正文在前台与后台两种PowerShell均实测通过，共12项；相关测试合计88项通过，另覆盖暂态失败退避后沿用同一任务恢复且计划始终启用。

掘金实机搜索“AI工具”无选项，“人工智能”已核实可选。趣造AI自动生成的掘金文章固定使用“人工智能”主题；已有素材仅将“AI工具”归到该上级主题并去重，其他未知标签仍须精确核验。原始任务快照保持，实际选定标签写入回执platform_tags。相关素材及文章执行测试覆盖跨平台隔离、未知标签拒绝与原正文不变。

本轮最终验证：107项相关测试、12项三平台双PowerShell空框检查和3项正式页面计划/回执检查通过。三个授权的当天原稿均已真实提交并核验原账号正文、作者与结果链接；未以测试额外发帖、未发送评论。服务守护和原每日01:00帖子计划均已恢复。公开可见性仍按回执证据单独表述。

## 2026-10-16 跨天结果页与回执核验

掘金已完成任务的自有标签页允许同ID的 HTTPS /spost/ 到 /post/ 跳转，仅在不存在未决草稿时用于次日打开编辑器；不同ID、域名、端口、查询参数或未决草稿仍停止。知乎等文章结果页按一个内容子树重建全文，保留平台自动插入的实体链接显示文字，对原稿链接核对真实目标；只接受标题之后、正文之前的原账号作者。不会用全站登录头像、其他文章或评论补齐缺失证据。

结果不明任务的补录保留原提交时间、占位回执及原任务快照，状态仍为 recorded/user_reported，不伪装为平台API成功。补录不触发发送，未知结果不得续发。每日01:00只发1篇、评论0；00:00素材准备和真实平台保护规则不变。

针对性验证：三个连续模拟日期，每天重建服务和浏览器状态后执行三个平台各1篇，直接经过实际频道跳转及文章核验代码；重复tick和服务重启不增发；手动暂停阻止次日发送。实机结果、账号与正文只保存outputs，不提交Git。

掘金结果页的标题Text可能为“原题 审核中”；标题定位仅在掘金上剥离这个有空白分隔的已观察状态后缀，仍要求剩余标题精确一致。审核中仅代表本人可见且平台已接收，不代表审核通过或公开可见。三日集成场景也覆盖这种标题，防止只测试已审核的历史结果页。
