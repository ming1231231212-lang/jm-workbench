5. 保存生产数据库与源码回滚点，检查在途任务，部署并核对业务数据与服务守护，Git提交上传。pending

## 实现边界

- 在独立Git worktree研发，正式工作台继续使用旧版直到验收通过。
- 不导入原型演示账号、内容、模拟推进和localStorage业务状态。
- 所有测试使用隔离数据库与模拟平台；生产页面只做必要读取。
- 每日计划沿用后台每日1篇帖子、5条不同原帖评论的规则。单次发帖/评论由内容记录的新建入口处理，不伪造不支持的每日配额与频次。
- 登录核验与平台发布限制分别呈现；真实状态未核验时不声称公开可见。
- 后端记录超过200条时明确展示最近记录范围，今日汇总使用服务端全量任务计算。

## 文件职责

- community-v2-model.js：纯数据映射、筛选与导出；无网络副作用。
- community-v2-views.js：三个视图和详情HTML；统一转义外部内容。
- community-v2.js：界面状态与动作适配，调用既有CommunityUI和每日计划接口。
- community-v2.css / community-icons.js：已确认视觉与本地SVG。
- community/service.py：只读汇总与计划关联；执行逻辑不变。

测试证据与生产核验存于outputs/community-ui-v2，不提交真实账号、原文、令牌或数据库。
