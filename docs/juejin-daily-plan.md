# 掘金每日内容计划

用户授权：沿用贴吧规则，每天1篇文章、5条相关评论，由JM统一管理。使用既有掘金账号，自动匹配标签，不重复内容或目标。今日已发布的测试文章占用今日文章预算，不再安排第二篇。

## 实施

1. 核验掘金当前页面、身份、分类/标签、编辑器、评论入口和社区规则。
2. 单独的掘金浏览器适配器：身份核验、按标签有限读取、文章与顶层评论的一次提交；预检、明确拒绝、未知回执分开。
3. 每日计划扩展为按账号平台路由；文章自带标签；平台配额/风险隔离；历史网页发布登记计入预算与去重。
4. UI显示平台、分类、标签和每日结果；模拟适配器、浏览器契约、配额、去重与跨平台隔离测试。
5. 备份后部署，保留已有账号/内容/队列；配置实际素材与每天执行时间，检查首日任务、监控和GitHub CI。

## 边界

- 自然日：Asia/Shanghai，每平台每日1篇文章、5条评论，至少30分钟间隔，24小时不超过6次；同平台所有账号共享配额。
- 以原文与标签匹配具体主题，不重复粘贴营销话术；无匹配素材/目标时明确记录缺口。AI辅助内容标记，普通评论不带营销网址或联系方式。
- 不获取用户验证码，不自动更换账号/IP，不绕过验证；身份变化、页面变化、拒绝或未知结果停止。
- 发送先持久化占位。网页POST最多放行一次；未知结果不重新提交，页面关闭阻止网站后台重发。
- 固定素材库逐条消耗，耗尽时提示补充，不声称无限生成；帖子/评论全文、目标、匹配规则、标签和回执都可在JM查看。
- 新能力必须经模拟与页面证据验证；单元测试不向真实平台发送。

## 验证与部署

实现位于 `community/juejin.py`；每日计划、工作台账号同步、平台预算与原文快照沿用社区模块。掘金与贴吧可分别启用一份计划；某平台失败只暂停该平台。网页登记历史纳入间隔和每日额度，核验身份时补充历史内容去重映射，保持历史快照。

本地验证：367项Python回归通过（随后补充1项素材缺口监控测试）；45项Node测试通过；12项掘金UI、11项贴吧每日UI、7项浏览器提交契约验收通过。真实页面身份、17条标签候选与编辑器分类/标签已读取；文章、评论请求在本机拦截验证结构，测试没有发送至平台。真实业务只通过正式队列发送。

状态：完成。已备份部署并启用正式每日计划；历史业务表与账号配置保留。正式队列首条评论取得回执，匿名页面核验作者和正文一致，其余动作按间隔排队。368项Python、45项Node及30项Chrome检查通过，功能提交8c5e262的GitHub CI通过。素材与实际账号不进入仓库。

每日计划依赖本机服务与账号Chrome在线。文章和评论素材逐条消耗，缺口会在每日计划和巡检报告中提示；只读巡检每天10:30执行，不会绕过暂停或未知结果恢复发送。工作台仍将平台接收与公开可见性分开显示。
