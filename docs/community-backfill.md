# 社区历史补录

历史漏执行不能用今天的发送数抵消，也不能把“已登记”显示成“已发布”。社区的历史补录使用独立台账，原始任务、冻结快照、账号及回执保持不变。

## 数据和接口

- `community/backfill.py` 按已开始执行的计划创建日到指定截止日核对每天 1 篇帖子及指定评论目标（0–5 条）；首批支持贴吧、掘金。今天及未来日期不属于历史补录，单次最多 91 天。
- 原每日任务的所属日期优先于实际发送日期；人工登记占用名额，但仍显示人工登记，不转换为平台成功回执。
- `community_backfill` 用 `(plan_id, day, kind, slot)` 唯一约束保证重复登记幂等；已存在的未成功任务关联原内容，未使用的素材创建草稿。没有相关原帖时保留缺口，不编造评论目标。
- `POST /api/community/backfill/preview` 只预览缺口；`register` 持久登记并补充已有素材；`/{plan_id}/prepare` 核验原账号连接、只读发现相关原帖并补充草稿。接口沿用 Origin、令牌及代码版本保护。
- `/api/community/state` 的 `backfill` 返回逐日条目、正文关联及真实状态。界面位于“社区发布 → 发布计划 → 历史补发清单”，可展开逐日查看正文和原回执。

## 执行边界

补录和准备接口不提交到平台、不启动任务，也不恢复暂停计划。实际发布仍须使用有效执行连接、核验后的原账号以及现有提交流程。失败或未知回执不能自动重发；旧版本冻结任务仍需处理版本不一致。台账创建不代表这些问题已解决。

原计划不会重复使用历史台账预留的素材，用户明确登记的历史排队项也不会在换日时被自动清除。现有日额度、时间间隔、去重、风险锁和实际发送时间记录继续有效。历史评论目标不会悄悄修改未来每日评论配置。

## 验证

新增测试覆盖重复及并发登记、已有回执不变、人工登记去重、缺少原帖不伪造内容、日期范围、连接失败不发送、历史素材保留、历史队列换日及界面转义。2026-10-12 全量结果：435 项 Python、69 项 Node 测试通过。真实平台发送尚未作为本功能的验收结果。
