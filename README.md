# JM工作台

## Windows 免安装版

其他使用者推荐下载 [GitHub Releases](https://github.com/ming1231231212-lang/jm-workbench/releases) 中的 Windows x64 ZIP，**完整解压后双击「JM工作台.exe」**。不需要安装 Python、Node 或 FFmpeg。首次启动为空工作台，使用者添加自己的账号和内容；原作者的账号、密钥、浏览器资料和业务记录不会包含在发行包中。

数据保存在当前用户 `%LOCALAPPDATA%\JMWorkbench`。关闭网页不停止后台任务；双击「退出工作台.exe」停止，双击「环境检查.exe」查看环境状态。升级前退出旧包，新版本继续读取原数据。外接爬虫、平台账号权限及各社区的能力限制见[发行版说明](docs/windows-portable.md)。

下方为开发者从源码启动的方式。

将快手成人尾货收购、18+陪玩招募、多平台爬虫和 SAU 视频发布放进同一个本机工作台。界面分为任务、内容发布、数据、账号、设置；原有任务矩阵、平台能力、运行记录保留在对应页面内。

## 当前能力

| 模块 | 已实现 |
|---|---|
| 工作概览 | 任务进展、账号连接、累计数据、配置引导 |

| 账号管理 | 独立Chrome资料目录、打开登录、检查连接、快手身份绑定 |
| 平台接入 | 快手评论；快手、抖音、小红书、哔哩哔哩、微博、贴吧、知乎爬虫适配 |
| 数据中心 | 搜索、状态筛选、详情依据、分页、CSV导出 |
| 运行记录 | 队列、停止原因、操作日志、发送回执、平台限制 |
| 工作台设置 | Chrome和外部爬虫路径配置 |
| 内容发布 | 视频上传与预览、本地草稿、选择多个平台账号、立即/定时队列、暂停/继续/取消、逐账号回执 |

内容发布复用本机 SocialAutoUpload，接入其 Web API 支持的小红书、视频号、抖音、快手。账号登录仍在 SAU 中管理，从 JM 账号页打开；同名的评论账号与发布账号不自动合并。详见[发布接入与使用](docs/content-publishing.md)。

平台接入表示适配器入口已实现。其他平台需要对应账号登录；各平台的在线接口状态必须通过实际任务确认。快手基础关键词采集使用当前网页的准确搜索结果；快手评论采集和其他平台爬虫使用用户另行安装的MediaCrawler运行环境。

## 启动

需要Python 3.11及Google Chrome。Windows首次安装：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest
npm test
.\.venv\Scripts\python.exe -m jm_workbench
```

访问 `http://127.0.0.1:8776/`。以后双击根目录的“打开JM工作台.cmd”即可。首次配置从“账号管理 → 任务配置 → 任务矩阵”开始，外部爬虫路径在“工作台设置”填写。

专用Chrome会复用已有登录状态；本机有`Codex-Chrome/Open-CodexChrome.ps1`时，启动器优先使用该入口。服务只监听127.0.0.1；不适合作为公网服务直接部署。

## 后台自动恢复（Windows）

启用后由Windows计划任务运行独立检查器，每30秒核验本机服务；服务停止、端口空闲且原执行器锁释放时自动拉起。当前用户登录Windows后会启动检查器，每分钟的重复触发用于检查器退出后的恢复。无需保存Windows密码或管理员权限。

在项目目录执行：

```powershell
# 工作台已启动且健康时启用
.\scripts\Manage-JMWatchdog.ps1 -Action Enable
# 查看计划任务与最后一次检查结果
.\scripts\Manage-JMWatchdog.ps1 -Action Status
# 升级或维护前暂停自动恢复，保留正在运行的工作台
.\scripts\Manage-JMWatchdog.ps1 -Action Disable
```

自动恢复只管理后台服务，不点击“一键执行”、不恢复用户停止的业务任务、不解除风险锁、不重发未知结果。排队/等待的视频原样保留；中断中的步骤仍按原恢复规则暂停。端口被其他服务占用、执行器锁未释放或业务代码发生变化时只记录原因，不强行杀进程。连续启动失败按30/60/120/240/300秒退避，稳定运行2分钟后重置。

检查器通过`pythonw.exe`在后台运行，正常状态不弹窗、不发周期消息。检查状态和日志保存在`var/service-watchdog-state.json`、`var/service-watchdog.log`，服务启动日志在`var/service-watchdog-server.log`。电脑关机、休眠或用户尚未登录时不能执行本机任务；本功能不自动打开Chrome或重新登录平台。

升级/备份前先Disable，确认检查状态为disabled后再停服务；业务升级后先正常启动并核验新版本，再Enable确认新的守护版本。

## 使用逻辑

1. 添加平台账号。每个账号使用独立资料目录；打开浏览器登录后检查连接。
2. 新建任务：选择平台和业务，填写关键词及模板。爬虫不执行评论发布。
3. 在矩阵中勾选需要执行的账号和任务组合。
4. 点击“一键执行”。所有启用的组合先整体检查；任何配置有问题时，会列出原因。
5. 到运行记录查看执行、排队、等待时段或停止状态。数据中心查看结果和依据。

任务修改会保留历史快照；活动任务需先停止再编辑。停止后新的一键执行创建新批次，历史视频接触记录持续去重。服务重启时，排队/等待任务仍保留；正在执行的步骤会暂停，未确认发送会锁定平台。

## 发布边界

- 无逐条人员审核：成人尾货依据正文中的成人品类、自家经营及实物库存证据筛选；陪玩依据明确成年与本人求职意向筛选。无法确定的内容自动跳过。
- 关键词和昵称不能补足正文证据。详情必须精确绑定视频、作者和评论权限；发送前重新核对。
- 本版本使用文本证据，没有进行视频画面识别或语音识别。因此存在漏掉正文证据不足的目标的可能。
- 所有同平台账号共享频率限制和接触历史，不会通过换号或换IP继续执行受限任务。
- 读取间隔至少5分钟，每平台滚动24小时最多24批，08:00–23:00；评论间隔至少30分钟，滚动24小时最多5条，20:00–23:00内可缩短。
- 相同视频不重复接触，作者与相同评论文本7天内去重。不保证评论显示在其他用户端；收到评论ID才记为“平台已接收”。
- 发送先持久化占位；超时或未知回执不重发。平台限制暂停该平台的全部任务；本机连接问题单独处理。

## 外部爬虫

MediaCrawler是独立可配置依赖，JM仓库不包含它的源码、环境或账号数据。原项目许可证和平台使用条件保持原样；该集成不授予额外使用权。

每个爬虫批次有独立参数和结果目录；不修改外部共享配置，不导入旧`fix_cookies.json`，不启用代理池，不调用自动登录或验证绕过逻辑。单批最多10分钟、40次HTTP客户端请求，内容及评论数量受任务设置约束；遇平台限制停止，不进入旧重试流程。

## 数据、迁移与备份

本地配置、SQLite、运行参数及浏览器资料保存在`var/`；验收附件保存在`outputs/`。这两个目录均不上传GitHub。备份时先禁用自动恢复、停止任务及服务，再备份`var/`和外部引用的浏览器资料目录。

可用`python -m scripts.import_legacy --runtime <原爬虫目录> --profile <专用Chrome资料目录>`只读导入旧记录。迁入的候选只作为历史数据，不能直接触发评论；旧接触记录继续参与去重。`scripts/install_legacy_bridge.py`备份并将旧成人任务入口及F6入口改为观察JM队列，避免两套程序同时发布。

卸载或回退前先停止JM任务。旧入口备份在`outputs/legacy-backup-*`；回退也必须保留JM新增接触历史，避免重复联系。
